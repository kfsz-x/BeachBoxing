# Beach Boxing 原包基准

> 2026-11-19 更新：下文按取证轮次保留历史结论。涉及“仍近似”“未恢复”的旧条目，以文末最新核对和验收记录为准。

## 样本条件

- 2026-11-18，用户提供的 Unity 2022.3.34f1 离线 WebGL 包。Chrome 独立临时用户目录，新档开始。桌面 900 × 620，浏览器帧间隔中位数 16.67 ms，p95 16.70 ms（60 帧，非真机）；触屏模拟 432 × 768。
- 截图及分析原件保存在 `%TEMP%/BeachBoxing-reference/`，未将原包素材和反编译产物加入工程。桌面操作受帧率影响，以下时长是复跑起点。
- 原包 `poki-sdk.js` 使用离线奖励桩。广告、在线服务和外围奖励不纳入首版对照。

## 静态取证

- REA 6.8.0 解析 `global-metadata.dat` v31：34 程序集、3760 类型、23656 方法。UnityFS 中有两份场景数据（level0、level1），分别含训练与拳击组件。
- [Il2CppDumper 6.7.46](https://github.com/Perfare/Il2CppDumper/releases/tag/v6.7.46) Windows 发行包，在临时目录运行 `Il2CppDumper.exe reference.wasm global-metadata.dat dump`。识别版本 31、两个注册表，生成 `dump.cs`、`script.json`、`DummyDll`。重定向输入时，末尾等待按键报错；产物已生成并可解析。
- 用 WABT 解析 WASM 元素表，将 `script.json` 地址作为函数表槽关联到真实函数索引。例如 `BoxingController.Punch` 槽 4803 → func 28148；受击 func 28147 / 28136；训练 Update func 50065 / CompleteWorkout func 28165。
- 反汇编确认玩家初始生命、体力各以 50 为基数，训练属性作整数除法（除数 20）；对手生命、体力各以 20 为基数并叠加多个来源。首版用 R04/R06 实测结果锁定，不能推定第三位以后的通式。出拳时体力扣量随随机数和整数属性变化，玩家样本中的 2 不是通用常数。出拳函数含 0.10 秒、0.25 秒延迟调用；命中完整结束窗口仍待精测。
- 训练每次进度完成有独立的 `CompleteWorkout`；四类训练为胸、手臂、背、腿。首版的训练循环应按单次动作发放奖励，已完成的动作即使退出也保留。

## 对照阈值及未决项

- 新档值、首胜奖励、已解锁对手、重赛恢复与存档保持须逐项一致。生命、体力、格挡开场数值按 R04/R06 校验。
- 动作定时：当函数语义可确认，秒数以 WASM 为准，60 fps 对拍允许两帧误差（约 33 ms）；只凭截图观察的事件，如无连续帧样本，不作为精确计时依据。镜头以位置关系、是否保持双方可见和控制手感对照。
- 精确拳套碰撞几何、完整命中窗、双方 AI 行为、低体力全部分支和更后期对手需要补样。首版未知参数独立配置，按近似标注；真机多指、方向和摄像机留 M5 验收。
- 首版保留原包观察到的竖屏布局方向。使用同一场景切换区域，模拟出拳赛倒数及返场重置；记录这与原包跨场景加载的差异。


## 二轮核对：训练、拳赛与渲染

- 提供的原版 WebGL 包使用 Unity Built-in。导出的 `GraphicsSettings.asset` 中 `m_CustomRenderPipeline` 为 `{fileID: 0}`；`QualitySettings.asset` 中 `customRenderPipeline` 同为空。已解析的 IL2CPP 类型也未见 URP 管线资产类型。当前工程默认管线和质量档覆盖同为空。
- `WorkingOutManager.Update`（func 50065）按秒推进：空闲速度 0.5，按住时向 1.3 插值，点击瞬间置为桌面 3.5 或手机 5。达到 0.99 完成并清零。新档每次基础奖励 11；后续等级表和属性倍率未接入。
- `BoxingController.Punch`（func 28148）消耗 `Random.Range(1,3) + 手臂 / 700`；对手出拳为 `Random.Range(3,5) + 对手手臂 / 400`。玩家 `LoadMaxBlock`（func 28151）以背部属性提高格挡上限及格挡、体力、生命恢复速率。`Move`（func 28149）在举盾分支补充体力和生命。
- 举盾、有格挡值时扣格挡且当次不扣血；格挡耗尽继续举盾仍可恢复生命和体力，但当前格挡值为 0 时无法吸收命中。格挡恢复有 1 秒延迟。伤害按原包基础样本与属性系数实现；精确拳套碰撞和 AI 走位仍近似。
- 替换四项肌肉图标、训练进度条、战斗计量条、胜利徽章和低状态/受击遮罩为原版切图。动态文字沿用原包中的 LiberationSans，原包主 HUD 的 LilitaOne 字形及完整画面布局仍有差异。


## 三轮核对：训练站位与结束动作

从原包 level0 的 ChestPressMachine 序列化数据读取：`playerPos` 引用在胸部、手臂、背部器械上指向器械根节点；腿部器械引用其名为 `GameObject` 的子节点（本地 x=5.8）。`playerExitPos` 指向各自 `ExitPos`。当前运行时按器械实例变换这些原始坐标，不再套用统一的角色后移偏置。原包素材已归一化缩放，角色与器械接触的完整动作仍须录屏对照。

战斗结束后停止使用冻结的出拳计时驱动动画，胜者使用原包 BoxingArmature 控制器的 `PhotoShoot`，败者使用 `Boxing_Die`。后退使用 `Boxing_WalkBackward`。这些修正解决当前实现的动作状态问题；不等同于完成原包全部镜头和过场复刻。

## 四轮核对：原生场景、机位和判定

2026-11-19，原包通过本地 HTTP 服务只读复跑。新档桌面出生、四项训练、选人、倒数和拳赛的追加截图位于 `reference/original-extra`。背部器械有重名对象，最终用完整路径 `LEVEL0/LVL1/WorkoutArea (3)/GameObject/ArmsMachineInteractable (1)` 捕获；只传短名会错误地停留在出生画面。训练定点截图调用原包 `Interact`，不作为正常寻路证据。拳赛录像按 W 约 3.15 秒、E，再调用已显示选人页的 `PressFight` 进入。

- 原始 Workout/Combat 几何、地形、训练骨架和拳赛骨架已经转入预摆场景。统一比例 0.356；Terrain 单独克隆 TerrainData 并缩放尺寸、地形层 UV，因为 Terrain 不响应 Transform 缩放。
- 原训练机位来自原生 `ChestPressMachine` 字段，各项分别使用原生位置和旋转。自由移动桌面相机偏移 `(0,9.1,16.8)`，手机 `(0,18.53,32)`；均乘比例，角度 `(22.639,-180,0)`。训练玩家原生朝向为单位旋转，并非器械根朝向。
- 原拳赛桌面机位 `(-8.7,4.9,6.94)`；手机来自 `BoxingController.phoneCameraPos` 指向的 Transform 891：`(-12.77,5.96,12.84)`。旋转相同，归一化四元数约 `(-.021745,-.952166,.069781,-.296712)`。字段原件见 `reference/combat-cameras.json`。当前保留绕双方中点及距离的适配，不能据此宣称完整复原原生相机跟随算法。
- 源色彩空间为 Linear，太阳强度 0.94。两张地图的 lightmap 数组为空；已恢复各自 27 个环境光 SH 系数，未合并完整空间光探针体积。棋盘垫与动态 decal 使用兼容 Shader 和原贴图，字体使用原 Lilita SDF 图集、96 个字符与字形度量，均有来源记录。
- 玩家命中球源半径 2.09231，中心 `(-1.1088,3.434477,1.04832)`，启用时固定位置；敌人半径 2.449387，中心 `(-1.1088,1.907823,1.04832)`，跟随角色。源身体胶囊半径分别为玩家 0.75、敌人 2.25。全部按统一比例用于判定。
- 玩家出拳窗口 0.10–0.15 秒，周期 0.25 秒；敌人 Jab 第 4–7 帧、Straight 第 4–8 帧（60 fps）。独立规则测试覆盖开窗、关窗、远距离空拳、单次伤害和胶囊相交。
- Ramez 的距离出拳检查间隔 0.5 秒，Kyle 为 0.4 秒，初次检查自 Start 起 5 秒。低体力举盾、Ramez 横移与随机停走、Kyle 体力进退阈值均依据原生字段与代码。随机数发生器和重复低体力回调的调度未逐种子同步。
- 原版静态特效已经预摆：沙滩环境、脚步、汗水、拳套命中与格挡、胜利彩屑。原生训练 NPC 使用原模型和动作；随机游走、AFK、姓名牌与进阶体型未纳入核心玩法复刻。
