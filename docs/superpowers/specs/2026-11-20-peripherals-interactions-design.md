# 原版外围系统与可达交互修正

> 用户最新约束：仅以1920×1080横屏为开发和验收目标，不再安排其它分辨率适配。此前横竖屏证据作为历史保留。原UI内部坐标比例保留，实际目标视口固定1920×1080。

本轮依据用户的新截图和测试反馈扩展原先“核心闭环”范围。用户已明确授权继续推进、仅在实质信息缺失时询问；不再增加设计确认环节。继续使用当前 Unity 2021.3.14f1c1、Built-in、Linear 工程与现有 GameFrame/vivo SDK，用户手动打包。

## 目标

1. 四项属性恢复原进度填充、满格表现、千位格式、等级/体型关联。
2. 恢复原六位教练菜单：星星购买、金币升级、选择与装备、训练增益和持久化。
3. 恢复原六档签到：本地日期推进、独立可领状态、红点、金币/星星/教练奖励及幂等保存。
4. 恢复真实碰撞形状与图层语义，玩家从出生点用正常移动实际可达擂台和四种器械。擂台按原触发器自动进入选人；器械按原检测范围显示发光区、绿色 Interact/键位/手机按钮。
5. 对全部实际场景组件、按钮回调和可达页面建立模块差异表，区分已实现、近似、缺失、原包未实例化遗留代码和依赖外部配置的功能。

## 已证实依据

- 当前 HUD 只有四项数值，没有原 FillBar/BarFilledOBJ；原教练与签到入口、数据、页面均未接入。
- 训练区三层擂台地垫的 BoxCollider 当前尺寸为原版两倍。原角色 layer7 只忽略 NPC layer8；当前自定义 CapsuleCast 未保持该图层语义。
- 原擂台 FightMenu 触发器进入即开选人，不要求 E。器械使用脚部上方 OverlapSphere、交互图层与原 SphereCollider；不能继续用统一的 1.6 米中心距离代替。
- 原等级阈值 `[0,1000,3000,6000,10000,15000,23000,33000,45000,70000,100000]`。四项全部满格才允许升级；升级保留属性。数值大于999显示两位小数加小写 k。
- 教练 Cody/Dion/Nova/Zara/Serena/Yui；星价 `[-1,50,200,-1,500,900]`。Cody/Zara 来自签到。升级金币消耗 `8*当前教练等级+8`；源训练增益使用已装备教练的四项百分比并截断整数。
- 签到奖励依次为 Cody、3000金币、60星、10000金币、100星、Zara。原日期变化只推进一档，不按缺席天数补多档；每档只能领取一次，不强加连续签到和七日循环。
- 原包未实例化 Locker/Loot/Potion/多人管理等代码，不将这些代码名称直接当作当前游戏缺失模块。

来源见 `docs/beach-boxing/evidence/*-audit-2026-11-20.json` 与 `.superpowers/sdd/2026-11-20-peripherals-interactions/native-dump/`；不从截图猜价格或奖励。

## 实现选择

采用“保留现有流程、补原规则与预摆视图”的方案。直接移植原 MonoBehaviour 会引入失效脚本、原平台 SDK 和运行时实例化；只添加按钮占位无法闭环。规则与存档使用小型独立 C# 单元，显示继续使用原素材和 OriginalSdfText；Editor 显式迁移工具将原界面、触发器、发光区保存到场景，运行时只修改已绑定对象。

## 数据与边界

现有 `PlayerProgress` 旧字段及用户存档保持；新字段为可向后兼容的等级、教练所有权/等级/装备、签到日期/索引/已领取掩码。历史 v1 存档缺字段时补默认值，不清档、不将诊断进度写入用户档。金币、星星与训练增益统一通过规则调用，拒绝重复领奖、负余额、未拥有装备和非法索引。

原广告回调必须成功后才发放双倍训练。编辑器可以明确标识的模拟成功/失败；vivo 真广告依赖实际广告位配置，缺配置时不得虚发奖励。日期按设备本地日历；测试通过注入日期而非修改系统时间。

本轮不重做渲染管线、现有字体算法和拳赛物理。保存场景前后验证对象引用、原材质与已有手调位置。后续模块差异表逐项列出验收边界，不再将规则测试通过等同于完整一比一。
