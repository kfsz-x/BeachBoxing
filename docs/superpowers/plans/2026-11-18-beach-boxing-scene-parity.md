# Beach Boxing 后续开发计划：原版画面对照与场景预摆

2026-11-18。本计划接替原计划 M3–M5 的场景、表现与验收安排。已有训练、存档、两名对手、首胜和重赛逻辑作为回归基线。执行时使用 executing-plans 和 Unity MCP。玩法依据见 [原包基准](../../beach-boxing/reference-baseline.md)。

## 交付标准

打开 `Assets/BeachBoxing/Scenes/BeachBoxing.unity`，在未进入 Play 时即可选择和移动训练器械、人物、擂台、相机、灯光、HUD 和特效发射器。保存、关闭、重开场景后，人工调整仍生效。在 Inspector 内调整训练入口或相机后，下次运行直接使用新设置。

沿用 Unity 2021.3.14f1c1、Built-in、GameFrame 启动与菜单、vivo SDK 和现有存档键。默认一个玩法场景预摆训练区与拳赛区，分别设根节点。原包分属两张地图，两区采用各自局部坐标和源层级，切换时启停已摆放对象。菜单进入玩法沿用现有场景入口。重赛、换对手、训练及结算仅改变已绑定对象的状态。画面中的角色、地形、UI、字体、贴图、动画、音效、特效素材均追踪到原包。

## 已核实的起点（计划制定时）

- 当前玩法场景文件仅保存 1 个 GameObject，没有 Camera、Light、Terrain、Canvas 或 ParticleSystem。BeachGameFlow.Start 构建 BeachStage 和 BeachHud，OriginalArt.Place 在运行时实例化资源。硬编码的区域边界、靠近坐标和界面锚点会使场景调整失效。
- 原版离线 WebGL 为 Unity 2022.3.34f1。导出的 Workout.unity 有 1 个 Terrain、2 台相机、1 盏灯、2 个 Canvas、666 个 RectTransform、10 个场景内 ParticleSystem。Combat.unity 对应为 1、4、1、6、404、8。两场景均引用天空盒及各自的 LightingData。数量用于定位依赖，实际呈现应由启用状态和原包运行画面确认。
- 附件记录当前编辑器表现。原包参考 desktop-01 与 mobile-01 显示左侧四条纵排属性、角色头顶姓名与等级、独立训练地垫。竖屏出现手势引导。不同截图的角色位置、手臂数值、视口和输入模式有差异，精确对比前须同步。
- 原包导出件、原生字段和截图足够启动。编译后的 Shader、烘焙贴图、字体图集及粒子材质能否在 2021.3 完整还原，要逐项验证。上轮通过的 EditMode 16 项、PlayMode 17 项检验的是逻辑与引用，视觉验收单独记录。

## 执行顺序

### P0　固定参考画面和来源

- [x] 从用户提供的包复跑原版。整理 Workout、Combat 场景、Prefab 和依赖的 fileID/GUID。原始参照保存在工程 Assets 外；将关键截图、版本、保存状态、输入步骤和取帧时刻归档到稳定路径，避免临时目录清理后丢失。
- [x] 录制桌面 900×620、触屏 432×768。再按附件实际游戏视口补一张横屏同状态图。统一新档出生位置与朝向，另留固定训练属性的战斗档。
- [ ] 固定对照点：沙滩出生、靠近器械、四项训练动作顶点和回位、选人、擂台倒数、近身出拳、格挡受击、低生命、胜利、败北、重赛。记录 Game View 尺寸与输入模式。
- **交付**：每个对照点均能从同一存档和操作序列复现。优先补齐手机端拳赛、训练器械侧面和连续命中录像。

### P1　建立可编辑场景，解除运行时造景

- [x] 在现有玩法场景序列化 Training、Combat、Presentation 三组。训练组保存训练角色、四台器械、行走边界和触发器；拳赛组保存参赛角色、两位对手、碰撞体、出生点及边界；表现组保存界面、相机、灯光、AudioSource 与可复用特效槽。层级可沿用原包命名。
- [x] 用一次性 Editor 导入工具或 Unity MCP 从导出件转入静态对象，保留 Prefab 连接、原始父子变换和修改记录。导入器仅在明确执行时写入目标；重复执行应预览差异，避免覆盖人工调整。
- [x] 将 BeachGameFlow、BeachStage、BeachHud、BoxerView、TouchControl 的依赖绑定到序列化组件和引用。交互范围、玩家与对手出生点、镜头目标及擂台边界从场景对象读取。移除主流程里资源按名查找、创建 HUD、造地面和换模型实例的路径。编辑时提示缺失引用。
- [x] 检查 Framework 的 EventSystem、AudioListener、相机与新场景的启用关系。保存后从菜单进入，训练、选人、重赛、返回期间记录对象引用，验证预摆实例复用，按钮事件单次触发。
- **交付**：编辑模式可看见并选择两区、全部 HUD 状态面板与特效。移动一个器械和一个 UI 按钮并保存，重开场景验证画面和交互一起移动。默认视图展示训练区；其他面板可通过 Hierarchy 单独预览。

### P2　恢复空间布局、角色和镜头

- [x] 从原包两张地图取同一层级下的 TerrainData、地形层、海岸、植被、岩石、草、地垫、训练区、擂台及装饰。记录源与目标根变换，把既有站位、器械和出口重新绑定到预摆层级。
- [x] 分别核对训练角色与拳赛角色的骨架、网格、面部、头发、肌肉、服装和拳套启用组合。依据原包对应场景中角色的实际绑定配置模型与 Animator。
- [x] 恢复训练自由移动、各器械、选人、进擂台、对战和倒地镜头。读取原相机父级、位置、旋转、FOV、裁剪面和跟随目标；脚本覆盖的参数用原版实机位截图和连续帧校准。
- **交付**：做“出生沙滩＋正面擂台”两张同状态叠图。先对齐人物高度、地平线、器械位置、擂台绳索与地垫边缘，再进入材质调校。四项训练各核对手与握把、脚与地面、动作顶点与出口落点。

### P3　还原灯光、材质和 Shader

- [x] 对训练场、擂台分别记录原版 RenderSettings、色彩空间、Quality、主光方向和强度、阴影、环境光、天空盒、反射和烘焙光照。验证导出的 LightingData 及 lightmap 纹理、renderer 索引和 scaleOffset。
- [x] 单场景共享全局渲染设置。为两区预置需要的天空盒、光照纹理、反射和参数引用。能共存的 lightmap 合并索引；分区启用灯和反射探针，切区时应用已绑定的全局参数。用训练→拳赛→返场三张图检验恢复。
- [x] 逐类核对皮肤、拳套、器械、沙地、棋盘垫、海水、植被、UI 与粒子。查原 Shader、材质属性、主贴图及 UV 缩放、透明混合、关键字、渲染队列和纹理导入设置。针对不兼容 Shader 仅重建有原包证据的可见效果，继续使用原版贴图，记录剩余差异。
- **交付**：同光位、同机位截图中可核对沙地纹理尺度、地垫格数、角色高光、接地阴影、海水透明层。逐材质确认无缺图、粉材质和非预期回退。

### P4　按原版 Canvas 重建界面

- [x] 把原版 Canvas 层、CanvasScaler、RectTransform、锚点、Pivot、排序、遮罩、九宫格边框、填充方向及按钮状态绑定到场景。恢复四条纵排肌肉属性、人物头顶信息、交互标识、手势引导、选人卡、拳赛数值、倒数及结算。
- [x] 核对桌面键鼠与触屏下各元素的显示条件。用真实起始状态恢复附件里缺少或位置不同的要素。训练区中可见的外围入口纳入布局，对应的非核心系统仍按原有范围管理。
- [x] 核对 LilitaOne 字形、图集、材质、描边和行距，优先从原包恢复 TMP 字体数据与字符映射。若只能恢复部分字形，把缺失字符和对应页面记录为未通过项。
- **交付**：横屏和竖屏逐页并排截图。四条属性、右侧菜单、提示和战斗按钮无拉伸；命中区与可视按钮一致。检查安全区、移动与格挡双指、面板隐藏后触点释放。

### P5　动作、粒子、音效与拳赛手感

- [x] 对照原版动画状态、片段与过渡，还原训练器械同步运动、拳套接触、后退、格挡、受击、倒地及胜利表现。用 REA 和现有 Il2CppDumper 产物定位判定启停及 AI；以源碰撞形状、位置和原包逐帧观测替换近似距离和决策参数。
- [x] 预摆原版训练增益、汗水、命中、格挡、低血量、胜利等实际存在的特效。检查粒子材质、层级、模拟空间、排序、时长和触发帧；同样核对音效、震屏、HUD 与伤害发生时刻。高频反馈使用场景中预置的可重播实例。
- **交付**：在相同距离和操作下对照空拳、命中、格挡三段短片；逐项记录扣值、反馈首帧、持续时间及重复触发。重赛与返场后粒子、音频、镜头、输入和人物状态复位。

### P6　编辑器验收与 vivo 交接

- [x] 用 Unity MCP 从 Init→菜单→玩法走正常入口。记录运行前后层级和缺引用清单，运行 EditMode、PlayMode。验证已有进度读档、训练保存、两位对手、胜败、首胜奖励与重赛。
- [ ] 每个 P0 对照点归档原版图、复刻图、叠图或差异图与差异说明。静态画面使用同视口、同角色位置与同存档。建议首轮容差：HUD 边界偏差不超过 4 px，人物与擂台关键点偏差不超过视口短边的 1%，60 fps 动作首帧偏差不超过 2 帧。容差用于发现和追踪差异；缺少原版物件、明显材质错误、拉伸、错误动作或遮挡均单独修正。随机粒子对照发射位置、数量区间、颜色和持续时间。
- [x] 更新现有 vivo 交接清单并写明编辑器实测范围。用户手动打包并验证真机触控、画面裁切、Shader 与帧率。真机结果与编辑器结果分别登记。

**首个评审节点**为 P0–P3 的训练场出生画面。交付一份可手调的场景、一组原版与编辑器同机位对照图，以及仍有差异的项目。该节点通过后，同一套数据和验收方法继续覆盖完整 HUD、四项训练与两场拳赛。
